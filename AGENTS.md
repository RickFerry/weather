# AGENTS.md — Weather CLI App

## Project Overview
Implementation of a console weather application supporting:
- Default city weather display
- All registered cities weather
- City search and addition
- City removal
- Default city management
- Settings (°C adjustment)

All data stored locally in `cities.json`. Uses OpenMeteo API for weather data.

## Key Facts
- **Runtime target:** Node.js (TypeScript compiles to CommonJS, not Bun.js)
- **Package type:** CommonJS (`"type": "commonjs"` in package.json)
- **Main entry:** TypeScript `src/index.ts` → `dist/index.js` (fully implemented, not a stub)
- **Scripts:** Available via package.json
- **Architecture:** CLI app with data persistence layer

## Developer Commands
- `tsc` - TypeScript compiler check
- Build TypeScript with TypeScript directly (no Bun)
- `node dist/index.js` - Run the CLI after build

## Directory Structure
- `src/` - Source code (layered architecture)
  - `actions/` - User actions (getWeather, addCity, removeCity, setDefaultCity, settings, forecast, listCities)
  - `presentation/` - CLI interaction (menu.ts, input.ts, output.ts)
  - `storage/` - Data persistence (citiesStorage.ts, settingsStorage.ts) on cities.json
  - `types/` - Shared TypeScript contracts (City, Weather, Settings, MenuOption)
  - `api/` - External API integration (http.ts, geocoding.ts, weather.ts)
  - `utils/` - Reusable helpers (format, colors, constants, time)
  - `index.ts` - Entry point and main loop
- `dist/` - Build output (generated by tsc)
- `cities.json` - Local data storage
- `tsconfig.json` - TypeScript config

## Setup
- Dependencies installed via npm/Node.js
- TypeScript used for type safety
- Jest (ts-jest) for testing

## Workflow Notes
